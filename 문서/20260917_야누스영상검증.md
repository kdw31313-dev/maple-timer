# 야누스 영상 검증 — 로컬 수정본

## 확정 요구

고정 만료 타이머를 사용하지 않는다. 아이콘 존재 확인 후 감시를 시작하고, 실제 부재가 지속되면 사이트 소리와 텔레그램을 한 번 요청한다. 영상 시작 때 이미 아이콘이 보이는 경우에도 존재 확인 후 감시한다. 600ms 활성 확인과 1.2초 부재 확인은 영상 노이즈 방지 기준이지 사용 후 만료 시간 예측이 아니다.

## 구현

- 전용 아이콘 판별기, 독립 상태 처리, 별도 Worker 실행을 작성했다.
- 타이머 숫자는 비교에서 제외한다. 최초 탐색 기준과 이미 확인된 슬롯의 반투명 변화 허용 기준을 분리했다.
- 첫 영상의 0/5/10/15/20/25/30/35초 외곽 표본 8개를 추가했다. 두 번째 영상은 표본 추출에 사용하지 않았다. 다만 두 영상의 결과를 보며 개발했으므로 완전히 독립된 최종 평가 데이터는 아니다.
- 이전 버프 전체 판별기와 종료 임박 알림은 운영 야누스 경로에서 호출하지 않는다.

## 중요한 정정

초기 재생 도구가 YUV 영상의 홀수 높이 259를 258로 반올림하는 것을 놓쳐 프레임 경계가 틀렸다. `crop exact=1`과 바이트 수 나머지 검사를 추가했다. `기존판별결과`, `신규판별결과`, `추가표본_*` 결과는 무효이며 성능 비교에 사용하면 안 된다. 처음 보고한 2.7초 조기 알림 및 처리 시간도 철회한다. `정정_*`는 프레임 경계를 고친 중간 버전, `추적보완_*`만 최종 판별 결과다.

## 남은 검증과 적용 상태

- 알림은 모의 수신기로 확인했다. 실제 사이트 소리와 Telegram 수신, 브라우저 Worker의 실시간 영상 공유 시험은 미완료다.
- Worker는 룬·거탐 UI 실행과 분리했지만 전체 CPU 부하가 사라지는 것은 아니다. 특히 두 번째 영상 최초/재탐색 지연이 크다. 오프라인 검사는 모든 샘플을 처리하지만 실제 Worker는 처리 중 프레임을 건너뛰므로 같은 시각을 보장하지 않는다.
- 다양한 배율·해상도, 야누스가 전혀 없는 일반 사냥 영상, 밝은 다른 창으로 전환하는 상황에 대한 추가 검증이 필요하다.
- 상태·Worker 연결 및 기존 룬·거탐 회귀 테스트 결과는 별도 명령 실행으로 확인한다. 두 영상만으로 완벽한 인식을 보장하지 않는다.
- 이전 `20260917_야누스복구_진행기록.md`의 ‘원본 영상 없음/판별기 재사용 중’은 이번 작업으로 갱신되었다. 운영 사이트 미배포, 기본 꺼짐 유지.
